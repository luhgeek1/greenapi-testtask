# MAX · GREEN-API

Простой веб-чат для отправки и получения текстовых сообщений в MAX. Реализация [задания на React (v5)](https://drive.google.com/file/d/1Ut39kkIs0QK-swnCsIPJc6pNqVIVGOD2/view), с минимальным интерфейсом по структуре веб-чата MAX.

React 19, TypeScript, Vite. Для запросов используется `fetch`; сервер и переменные окружения не нужны.

## Локальный запуск

Нужны **Node.js 22.12+** и npm.

```bash
git clone https://github.com/luhgeek1/greenapi-testtask.git
cd greenapi-testtask
npm ci
npm run dev
```

Откройте адрес, который выведет Vite (обычно `http://127.0.0.1:5173`). Если порт занят, Vite выберет следующий свободный.

```bash
npm run build
npm run preview
```

`build` проверяет TypeScript и создаёт `dist/`; `preview` показывает production-сборку локально.

## Настройка GREEN-API

1. В [личном кабинете](https://console.green-api.com/) создайте инстанс **MAX** и авторизуйте его своим аккаунтом MAX. Инструкция: [перед началом работы](https://green-api.com/v3/docs/before-start/).
2. В настройках инстанса оставьте `webhookUrl` пустым и включите получение уведомлений о входящих сообщениях и файлах (`incomingWebhook: "yes"`). Подождите около минуты после изменения настроек. [Настройка HTTP API](https://green-api.com/v3/docs/api/receiving/technology-http-api/).
3. Скопируйте `idInstance`, `apiTokenInstance` и **точный `apiUrl` этого инстанса**. Для MAX это может быть, например, `https://3100.api.green-api.com`; используйте значение из своего кабинета.
4. Введите их на странице входа. Приложение проверяет авторизацию, тип инстанса и настройки получения; самостоятельно настройки инстанса не меняет.

## Как проверить переписку

1. Введите номер получателя в международном формате, например `+7 999 123-45-67` или `+375 29 123-45-67`, и нажмите **«Создать чат»**. Текущий MAX API поддерживает поиск по телефону для РФ и Беларуси. Получатель должен иметь аккаунт MAX с доступным поиском по номеру.
2. Напишите сообщение и отправьте кнопкой или Enter. Shift + Enter добавляет новую строку. Максимум — 4000 символов.
3. Ответьте с MAX-аккаунта получателя. Ответ появится в соответствующей переписке без перезагрузки.
4. Проверьте второй чат: сообщения и черновики должны оставаться в своих чатах. Непрочитанные ответы отмечаются в списке.
5. Нажмите кнопку выхода (на телефоне сначала вернитесь к списку чатов). Учётные данные и локальная переписка будут очищены, запросы отменены.

## Интеграция и ограничения

| Метод                                                                                                         | Назначение                                     |
| ------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| `getStateInstance`, `getSettings`                                                                             | Проверка инстанса при входе                    |
| [`checkAccount`](https://green-api.com/v3/docs/api/service/CheckAccount/)                                     | Получение MAX `chatId` по телефону             |
| [`sendMessage`](https://green-api.com/v3/docs/api/sending/SendMessage/)                                       | Отправка текста в найденный `chatId`           |
| [`receiveNotification`](https://green-api.com/v3/docs/api/receiving/technology-http-api/ReceiveNotification/) | Последовательный long polling входящей очереди |
| [`deleteNotification`](https://green-api.com/v3/docs/api/receiving/technology-http-api/DeleteNotification/)   | Подтверждение обработки уведомления            |

У MAX входящий `chatId` отличается от телефона. Поэтому номер сначала преобразуется через `checkAccount`, а переписка связывается по возвращённому идентификатору. [Правила MAX chatId](https://green-api.com/v3/docs/api/chat-id/).

Получение идёт одним последовательным циклом; после обработки уведомления подтверждается его `receiptId`. При сетевой ошибке применяется пауза с увеличением интервала, при ошибках доступа получение останавливается с возможностью повторить. Повторно полученные сообщения не дублируются. Сервисные уведомления и вложения подтверждаются, но не отображаются: задание требует только текст в личных чатах. Поддерживаются обычный текст и текст со ссылкой.

Галочка у исходящего сообщения означает **приём API в очередь**, а не доставку или прочтение. POST отправки автоматически не повторяется: при потере ответа это могло бы отправить сообщение дважды. При ошибке черновик сохраняется; перед повторной отправкой проверьте MAX.

Токен хранится только в памяти вкладки: без localStorage, sessionStorage, cookies и логирования запросов. Обращения идут непосредственно к HTTPS-серверам GREEN-API; адреса других доменов отклоняются. Переписка также хранится только в памяти и очищается при выходе или перезагрузке. История до подключения не загружается; в очереди GREEN-API могут быть уведомления за последние 24 часа.

Используйте один активный клиент получения на инстанс. Несколько вкладок или другой потребитель HTTP-очереди будут забирать уведомления друг у друга.
